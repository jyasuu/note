Here's the standard way to log method input/output in Spring Boot using **AOP (Aspect-Oriented Programming)** — it keeps logging out of your business logic entirely.

## 1. Add dependency

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
```

## 2. Create a logging aspect

```java
@Aspect
@Component
@Slf4j
public class LoggingAspect {

    @Around("@annotation(Loggable)")
    public Object logMethod(ProceedingJoinPoint joinPoint) throws Throwable {
        String methodName = joinPoint.getSignature().toShortString();
        Object[] args = joinPoint.getArgs();

        log.info(">> {} - args: {}", methodName, Arrays.toString(args));

        long start = System.currentTimeMillis();
        Object result;
        try {
            result = joinPoint.proceed();
        } catch (Throwable ex) {
            log.error("!! {} - threw: {}", methodName, ex.getMessage());
            throw ex;
        }
        long duration = System.currentTimeMillis() - start;

        log.info("<< {} - result: {} ({} ms)", methodName, result, duration);
        return result;
    }
}
```

## 3. Create a custom annotation

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Loggable {
}
```

## 4. Use it on any method

```java
@Service
public class OrderService {

    @Loggable
    public Order createOrder(OrderRequest request) {
        // business logic
        return new Order(...);
    }
}
```

Calling `createOrder(...)` now automatically logs:
```
>> OrderService.createOrder(..) - args: [OrderRequest(...)]
<< OrderService.createOrder(..) - result: Order(...) (12 ms)
```

## Alternative: log everything in a package (no annotation needed)

```java
@Around("execution(* com.example.myapp.service..*(..))")
public Object logAll(ProceedingJoinPoint joinPoint) throws Throwable {
    // same body as above
}
```

## A few practical notes

- **Sensitive data**: don't log full objects if they contain passwords, tokens, or PII — override `toString()` selectively or mask fields.
- **Large payloads**: truncate `args`/`result` strings if they can be huge (e.g., file uploads).
- **Performance**: AOP has minimal overhead, but avoid `@Around` on extremely hot paths if you're logging at `INFO` in production — gate it behind `DEBUG` level instead:

```java
if (log.isDebugEnabled()) {
    log.debug(">> {} - args: {}", methodName, Arrays.toString(args));
}
```

Good instincts — those are the three things that bite people in production. Here's how to handle each.

## 1. Masking sensitive data

Best approach: a custom annotation on fields, checked via reflection before logging.

```java
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Sensitive {
}
```

```java
public class LogSanitizer {

    public static String sanitize(Object obj) {
        if (obj == null) return "null";
        try {
            StringBuilder sb = new StringBuilder(obj.getClass().getSimpleName()).append("(");
            for (Field field : obj.getClass().getDeclaredFields()) {
                field.setAccessible(true);
                sb.append(field.getName()).append("=");
                if (field.isAnnotationPresent(Sensitive.class)) {
                    sb.append("***MASKED***");
                } else {
                    sb.append(field.get(obj));
                }
                sb.append(", ");
            }
            sb.append(")");
            return sb.toString();
        } catch (Exception e) {
            return "[unloggable: " + obj.getClass().getSimpleName() + "]";
        }
    }
}
```

```java
public class LoginRequest {
    private String username;

    @Sensitive
    private String password;

    @Sensitive
    private String token;
}
```

Then in the aspect, replace `Arrays.toString(args)` with sanitized versions:

```java
String argsStr = Arrays.stream(args)
        .map(LogSanitizer::sanitize)
        .collect(Collectors.joining(", "));
log.info(">> {} - args: [{}]", methodName, argsStr);
```

This is the same pattern Jackson uses for `@JsonIgnore` — just applied to logging instead of serialization.

**Quicker alternative** if you don't want reflection: override `toString()` on your DTOs manually and just never print raw field values in the aspect — only call `.toString()` on the object. Less automatic, but zero magic.

## 2. Large objects — truncate before logging

Simple length-cap helper:

```java
public class LogSanitizer {
    private static final int MAX_LENGTH = 500;

    public static String truncate(Object obj) {
        String str = String.valueOf(obj);
        if (str.length() <= MAX_LENGTH) return str;
        return str.substring(0, MAX_LENGTH) + "... [truncated, " + str.length() + " chars total]";
    }
}
```

Apply it after sanitizing:

```java
log.info(">> {} - args: {}", methodName, truncate(argsStr));
log.info("<< {} - result: {}", methodName, truncate(sanitize(result)));
```

For things like file uploads (`byte[]`, `MultipartFile`, `InputStream`), special-case them instead of trying to stringify:

```java
if (obj instanceof byte[] b) return "byte[" + b.length + " bytes]";
if (obj instanceof MultipartFile f) return "MultipartFile(name=" + f.getOriginalFilename() + ", size=" + f.getSize() + ")";
```

## 3. Configuring multiple packages via `application.yaml`

Pull the pointcut into config instead of hardcoding it in `@Around`.

**application.yaml:**
```yaml
app:
  logging:
    aop:
      packages:
        - com.example.myapp.service
        - com.example.myapp.controller
        - com.example.myapp.repository
```

**Config properties class:**
```java
@ConfigurationProperties(prefix = "app.logging.aop")
@Component
@Data
public class AopLoggingProperties {
    private List<String> packages = new ArrayList<>();
}
```

**Dynamic pointcut using a custom `Pointcut` bean:**

AspectJ's `@Around("execution(...)")` string can't read Spring properties directly at compile time, so build the pointcut programmatically:

```java
@Aspect
@Component
@Slf4j
public class LoggingAspect {

    private final AopLoggingProperties properties;
    private final AspectJExpressionPointcut pointcut = new AspectJExpressionPointcut();

    public LoggingAspect(AopLoggingProperties properties) {
        this.properties = properties;
        String expression = properties.getPackages().stream()
                .map(pkg -> "execution(* " + pkg + "..*(..))")
                .collect(Collectors.joining(" || "));
        pointcut.setExpression(expression.isEmpty() ? "execution(* void.none())" : expression);
    }

    @Around("dynamicPointcut()")
    public Object logMethod(ProceedingJoinPoint joinPoint) throws Throwable {
        // same body as before
    }

    @Pointcut
    private void dynamicPointcut() {
        // placeholder, real matching happens via DeclareParents or AspectJExpressionPointcut bean below
    }
}
```

In practice, the cleanest way to wire a *dynamic* expression is to register the pointcut as a Spring Advisor bean rather than fighting `@Aspect` annotations:

```java
@Configuration
public class LoggingAdvisorConfig {

    @Bean
    public Advisor loggingAdvisor(AopLoggingProperties properties, LoggingInterceptor interceptor) {
        String expression = properties.getPackages().stream()
                .map(pkg -> "execution(* " + pkg + "..*(..))")
                .collect(Collectors.joining(" || "));

        AspectJExpressionPointcut pointcut = new AspectJExpressionPointcut();
        pointcut.setExpression(expression);

        return new DefaultPointcutAdvisor(pointcut, interceptor);
    }
}
```

```java
@Component
public class LoggingInterceptor implements MethodInterceptor {
    @Override
    public Object invoke(MethodInvocation invocation) throws Throwable {
        // same logging logic, using invocation.getMethod(), invocation.getArguments(), invocation.proceed()
        return invocation.proceed();
    }
}
```

This way, adding a new package is just a one-line change in `application.yaml` — no recompiling, and it works differently per environment (e.g. verbose logging in `dev`, narrower scope in `prod`).

**Bonus: per-environment toggle**

```yaml
# application-dev.yaml
app.logging.aop.packages:
  - com.example.myapp

# application-prod.yaml
app.logging.aop.packages:
  - com.example.myapp.service.payment  # only log the sensitive stuff you actually need traced
```
